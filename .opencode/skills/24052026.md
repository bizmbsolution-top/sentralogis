# Catatan Update — 24 Mei 2026

## Observability: System Health Cards Live

### Masalah
Semua kartu System Health di `/owner/observability` (API Status, Database, Supabase, Active Users, Error Rate) menggunakan nilai **hardcoded** — tidak mencerminkan kondisi real-time.

### Perubahan
**File:** `lib/monitoring/mission-control.ts`

| Kartu | Sebelum | Sesudah |
|-------|---------|---------|
| **API Status** | hardcoded `'online'` | HEAD request ke `/api/cron/health` — `online` jika 200, `down` jika gagal |
| **Database** | hardcoded `'healthy'` | Query `audit_logs` via service role — `healthy` jika sukses, `error` jika error |
| **Supabase** | `client ? 'connected' : 'disconnected'` | Sama dengan Database (dari `runHealthCheck()`) |
| **Active Users** | hardcoded `1` | Distinct `user_id` dari `audit_logs` 15 menit terakhir (with `count: 'exact', head: true`) |
| **Error Rate** | `errors.length * 5` (selalu 0) | `fail / total * 100` dari `monitoring_checks` |
| **Queue Status** | hardcoded `'healthy'` | Masih `'healthy'` — tidak ada queue infrastructure |

### Detail Teknis
- Import `runHealthCheck()` dari `@/lib/monitoring/health-check` yang sudah ada
- `runHealthCheck()` sudah dipanggil di `Promise.allSettled` parallel dengan query lain
- Health checks memiliki timeout 5s — jika gagal, fallback ke nilai default (tidak nge-break dashboard)
- Auto-refresh tetap 30 detik via `setInterval` di page
