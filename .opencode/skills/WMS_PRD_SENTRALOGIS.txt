## 1. Ringkasan Eksekutif

### 1.1 Latar Belakang

SENTRALOGIS adalah platform SaaS multitenant logistik terintegrasi dengan SBU lengkap: Forwarding, Trucking, Warehouse, dan Clearance. Saat ini, operasional pergudangan masih berjalan secara semi-manual atau menggunakan sistem terpisah yang tidak terintegrasi dengan modul lain. Hal ini menyebabkan:

- **Inkonsistensi data stok** antar sistem
- **Keterlambatan penagihan** jasa gudang karena kalkulasi manual
- **Kesulitan tracking** barang multi-customer dalam satu fasilitas
- **Tidak ada visibilitas real-time** utilisasi gudang per zona
- **Profitabilitas per area** tidak terukur

### 1.2 Solusi yang Diusulkan

Sentralogis WMS adalah modul dalam platform logistik terintegrasi yang berfungsi ganda:
1. **Sebagai pendukung operasional** modul Forwarding (menerima Job Order inbound/outbound)
2. **Sebagai produk mandiri** untuk layanan 3PL Warehouse Service kepada pelanggan eksternal

### 1.3 Nilai Bisnis

| Stakeholder | Nilai yang Diberikan |
| :--- | :--- |
| **SBU Warehouse** | Otomatisasi operasional, tracking real-time, utilisasi optimal |
| **HQ Finance** | Kalkulasi tagihan otomatis, P&L per area gudang |
| **Customer Service** | Visibilitas stok customer, update status real-time |
| **Customer 3PL** | Portal mandiri cek stok, riwayat transaksi, invoice digital |
| **Manajemen** | Dashboard utilisasi, profitabilitas per zona, pengambilan keputusan berbasis data |

## 2. Visi & Tujuan Produk

### 2.1 Visi

**"Menjadi satu-satunya sumber kebenaran (single source of truth) untuk seluruh operasi penyimpanan dan penanganan barang di seluruh fasilitas tenants, yang mampu melayani kompleksitas multi-komoditi, multi-zona, multi-customer, dengan kemampuan penagihan yang fleksibel."**

### 2.2 Tujuan Spesifik (SMART Goals)

| Tujuan | Metrik | Target |
| :--- | :--- | :--- |
| **Akurasi Stok** | Selisih stok fisik vs sistem | < 0.1% per bulan |
| **Kecepatan Inbound** | Waktu dari barang tiba → status "Available" | < 15 menit |
| **Akurasi Tagihan** | Selisih tagihan manual vs otomatis | < 0.5% per bulan |
| **Utilisasi Gudang** | Persentase kapasitas terpakai terlaporkan | Real-time dashboard |
| **Customer Satisfaction** | Skor kepuasan customer 3PL | > 4.5/5.0 |

### 4.2 Prinsip Desain

1. **Satu Modul, Dua Mode Operasi:**
   - **Mode Internal:** Menerima Job Order dari modul Forwarding
   - **Mode 3PL:** Menerima Storage Contract langsung dari customer

2. **SBU sebagai Profit Center:** WMS mencatat biaya operasional internal dan menghasilkan revenue dari customer 3PL

3. **Inventory_ID sebagai Unit Pelacakan Terkecil:** Setiap kemasan fisik unik dilacak dengan ID sendiri

## 8. Aturan Bisnis & Validasi

### 8.1 Validasi Penyimpanan

| Aturan | Deskripsi | Konsekuensi |
| :--- | :--- | :--- |
| **COM-ZONE-MATCH** | Komoditi barang harus cocok dengan zona penyimpanan | ❌ Tolak putaway, tampilkan zona yang sesuai |
| **CAPACITY-CHECK** | Bin/lokasi tidak boleh melebihi kapasitas berat | ❌ Tolak, sarankan lokasi lain |
| **DIMENSION-CHECK** | Dimensi barang harus muat di lokasi | ❌ Tolak |
| **TEMP-MATCH** | Suhu requirement SKU harus sesuai dengan suhu zona | ❌ Tolak |
| **HAZMAT-ISOLATION** | Hazmat harus disimpan di zona khusus, tidak boleh campur dengan food | ❌ Tolak |
| **STACK-LIMIT** | Jumlah tumpukan tidak boleh melebihi limit SKU atau area | ⚠️ Warning, catat override |

### 8.2 Validasi FEFO/FIFO

| Aturan | Deskripsi | Konsekuensi |
| :--- | :--- | :--- |
| **FEFO-ENFORCE** | Barang dengan expiry paling dekat harus dipick duluan | ❌ Block scan jika staff scan batch yang lebih baru |
| **FEFO-OVERIDE** | Supervisor bisa override dengan alasan (damaged, customer request) | ⚠️ Catat di exception log dengan user dan alasan |
| **EXPIRY-BLOCK** | Barang expired tidak boleh dipick | ❌ Block, rekomendasikan quarantine |
| **EXPIRY-WARNING** | Barang akan expired dalam 30 hari | ⚠️ Notifikasi ke supervisor |

### 8.3 Validasi Kitting

| Aturan | Deskripsi | Konsekuensi |
| :--- | :--- | :--- |
| **BOM-VALID** | Semua komponen harus tersedia dalam stok | ❌ Jangan mulai jika stok kurang |
| **COMPONENT-SCAN** | Semua komponen harus di-scan sebelum output bisa digenerate | ❌ System menunggu scan lengkap |
| **WASTE-TOLERANCE** | Waste tidak boleh melebihi toleransi yang dikonfigurasi | ⚠️ Over-tolerance: supervisor approval |

### 8.4 Validasi Transfer

| Aturan | Deskripsi | Konsekuensi |
| :--- | :--- | :--- |
| **STOK-TERSEDIA** | Stok di gudang asal harus mencukupi | ❌ Tolak transfer order |
| **ZONA-TUJUAN** | Gudang tujuan harus punya kapasitas tersedia | ⚠️ Warning, tapi tetap bisa kirim |
| **IN-TRANSIT** | Stok tidak bisa dipindahkan lagi saat sedang in-transit | ❌ Block movement |

## 9. Integrasi Antar Modul

### 9.1 Integrasi dengan Modul Forwarding

| Dari Forwarding | Ke WMS | Mekanisme |
| :--- | :--- | :--- |
| **JO Inbound** | Receipt Order | Forwarding kirim `JO_Inbound_ID` → WMS buat `Receipt_Order` dengan link `Source_JO_ID` |
| **JO Outbound** | Picking List | Forwarding kirim `JO_Outbound_ID` → WMS generate picking berdasarkan FIFO/FEFO |
| **JO Stuffing** | Pallet Build-Up | Forwarding kirim daftar WO yang akan dikonsolidasi → WMS buat `Handling_Unit` dan assign isi |
| **Query Biaya** | Rate Engine | Forwarding tanya biaya handling → WMS kirim tarif spot jika tidak ada kontrak |

### 9.2 Integrasi dengan Shared Kernel

| Modul | Data yang Dipakai WMS | Data yang Diberikan WMS |
| :--- | :--- | :--- |
| **Vendor Master** | Data customer 3PL, vendor alat berat, vendor listrik | - |
| **Location Master** | Alamat gudang, port code | Bin location (jika dibutuhkan modul lain) |
| **Rate Engine** | Rate card handling, sewa per zona | Actual usage untuk kalkulasi |
| **Finance Ledger** | - | Transaksi tagihan gudang (AR), biaya operasional (AP) |
| **Document Vault** | - | Foto barang inbound, Packing List, Sertifikat Suhu |

### 9.3 Integrasi IoT (Cold Chain)

| Sensor | Data | Frekuensi |
| :--- | :--- | :--- |
| **Suhu** | Temperature_C | Setiap 15 menit |
| **Kelembaban** | Humidity_Pct | Setiap 15 menit |
| **Pintu** | Open/Close Event | Real-time |

**Webhook/API Call:** Sensor → IoT Gateway → WMS API → `Temperature_Log` table

**Alert Rule:** Jika suhu > threshold selama > 30 menit → Notifikasi Supervisor + Auto-quarantine stok di zona tersebut.
