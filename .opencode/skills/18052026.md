# Rencana Kerja Deployment Sentralogis (18 Mei 2026)

Fokus utama hari ini adalah mempersiapkan aplikasi Sentralogis untuk rilis produksi (Production Deployment) menggunakan platform Vercel dan menghubungkannya dengan domain utama `www.sentralogis.com`.

## 1. Persiapan Build & Optimasi (Pre-Deployment)
Sebelum di-push ke Vercel, kita harus memastikan tidak ada error saat proses _build_ di Next.js:
- [x] Menjalankan perintah `npm run build` di lokal untuk mendeteksi _Type errors_ (TypeScript) atau _ESLint warnings_ yang bisa menyebabkan build Vercel gagal.
- [x] Memperbaiki error _missing props_, _unused variables_, atau _React warnings_ (seperti `selected` di tag `option` yang baru saja kita atasi).
- [x] Memastikan semua dummy data console.log atau dev-tools script yang tidak perlu sudah dibersihkan/dikomentari.

## 2. Pengaturan Environment Variables (.env)
Vercel membutuhkan environment variables yang sama dengan `.env.local` untuk bisa terkoneksi dengan Supabase dan layanan lainnya:
- [x] Mengumpulkan semua _keys_:
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  - `SUPABASE_SERVICE_ROLE_KEY` (Sangat krusial untuk fitur Tenant Registration)
  - `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` (Sesuai `AGENTS.md` untuk Tracking Tower)
- [x] Menambahkan variabel di menu **Settings -> Environment Variables** pada project Vercel.

## 3. Proses Deployment ke Vercel
- [x] Mengkoneksikan repositori GitHub project `sentralogis` ke akun Vercel.
- [x] Mengatur Root Directory ke `./` (jika repo ada di root) dan Framework Preset ke **Next.js**.
- [x] Menjalankan proses _Deploy_ perdana dan memantau _Build Logs_ jika terjadi kegagalan (biasanya karena `package-lock.json` conflict atau TypeScript strict mode).

## 4. Konfigurasi Domain Utama (www.sentralogis.com)
Setelah aplikasi berhasil online dengan domain bawaan `.vercel.app`, langkah selanjutnya adalah _custom domain_:
- [x] Menambahkan domain `sentralogis.com` dan `www.sentralogis.com` di menu **Settings -> Domains** di Vercel.
- [x] Masuk ke panel DNS manager domain (misal: Niagahoster, Rumahweb, Cloudflare, atau tempat membeli domain) untuk mengatur record:
  - **A Record**: Arahkan `@` ke IP Vercel (`76.76.21.21`)
  - **CNAME Record**: Arahkan `www` ke `cname.vercel-dns.com`
- [x] Menunggu propagasi DNS (biasanya 10-30 menit) hingga Vercel berhasil men-generate sertifikat SSL (HTTPS) secara otomatis.

## 5. Post-Deployment Testing (QA di Production)
Mengingat ada perbedaan lingkungan antara lokal dan Vercel (seperti Edge runtime atau Serverless functions timeout), QA harus difokuskan pada:
- [ ] **Test Register Tenant:** Memastikan server action `registerTenantAdmin` yang menggunakan _Service Role Key_ tetap berfungsi di Vercel (karena mem-bypass RLS dan Auth).
- [ ] **Test Middleware Auth:** Memastikan user yang mencoba masuk tanpa token dilempar kembali ke halaman `/login`.
- [ ] **Test Load SBU:** Memastikan struktur modular SBU (Trucking, Warehouse) yang baru dibuat dirender tanpa error di production.
- [ ] **Test Google Maps:** Memastikan Maps dirender dengan benar, domain `sentralogis.com` harus didaftarkan dalam HTTP Referrers di Google Cloud Console agar API Key tidak diblokir.

---

> **Catatan Persiapan untuk Anda:**
> Pastikan akses login ke penyedia Domain Anda (untuk setting DNS) dan kredensial GitHub sudah disiapkan. Jika ada kendala dengan _build_ TypeScript, kita akan matikan strict build sementara di `next.config.js` (`ignoreBuildErrors: true`) agar bisa segera _live_.
