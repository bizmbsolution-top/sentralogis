## Project: Sentralogis Core Monitoring Platform

## Target Stack:

* Next.js

* Antigravity
* Future modules:

  * SBU Trucking
  * WMS
  * Forwarding
  * Finance
  * Procurement

---

# 1. Background

Sentralogis saat ini telah memiliki modul SBU Trucking dan akan berkembang ke:

* WMS
* Forwarding
* Finance
* Procurement

Kompleksitas sistem akan meningkat drastis:

* multi workflow
* multi user
* multi role
* multi transaction
* multi integration

Saat ini debugging masih manual dan reactive:

* menunggu user melapor
* sulit tracing bug
* tidak ada audit trail lengkap
* tidak ada anomaly detection
* tidak ada centralized observability

Sistem debugging modern diperlukan agar:

* masalah cepat ditemukan
* operasional tidak chaos
* data integrity terjaga
* founder non-technical dapat membaca kondisi sistem
* future scaling lebih aman

---

# 2. Goals

## Primary Goals

Membangun centralized observability system untuk:

* logging
* audit trail
* monitoring
* error tracking
* scheduled diagnostics
* workflow tracing
* anomaly detection

---

# 3. Non-Goals

Bukan:

* AI auto fixing
* auto healing distributed infra
* enterprise Kubernetes monitoring
* SIEM/security platform
* DevOps replacement

---

# 4. Core Principles

## 4.1 Traceability First

Semua critical action harus dapat ditelusuri:

* siapa
* kapan
* dari mana
* data sebelum
* data sesudah

---

## 4.2 Business Workflow Oriented

Debugging bukan per file.
Debugging berdasarkan:

* shipment flow
* trucking flow
* inventory flow
* forwarding flow

---

## 4.3 Low Cognitive Load

Founder non-technical harus dapat:

* memahami alert
* membaca health dashboard
* mengetahui prioritas

Tanpa membaca source code mendalam.

---

## 4.4 Modular Architecture

Monitoring harus reusable untuk:

* trucking
* WMS
* forwarding
* finance

---

# 6. System Components

# 6.1 Central Logger System

## Purpose

Standardized logging untuk seluruh aplikasi.

---

## Requirements

### Create:

```text
/lib/logger.ts
```

---

## Logging Levels

| Level    | Purpose                  |
| -------- | ------------------------ |
| info     | normal business activity |
| warn     | suspicious condition     |
| error    | failure                  |
| critical | operationally dangerous  |

---

## Example

```ts
logger.info('ASSIGN_DRIVER_START', payload)

logger.error('CREATE_JO_FAILED', error)
```

---

## Requirements

### Logs MUST contain:

* timestamp
* module
* action
* user_id
* reference_id
* correlation_id
* payload
* severity

---

# 6.2 Audit Trail System

## Purpose

Permanent business activity history.

---

## Database Table

```sql
audit_logs
```

---

## Columns

| Column         | Type        |
| -------------- | ----------- |
| id             | uuid        |
| created_at     | timestamptz |
| module         | text        |
| action         | text        |
| user_id        | uuid        |
| user_name      | text        |
| reference_type | text        |
| reference_id   | text        |
| correlation_id | text        |
| severity       | text        |
| old_data       | jsonb       |
| new_data       | jsonb       |
| metadata       | jsonb       |

---

## Mandatory Logging Actions

### Trucking

* assign driver
* create JO
* accept job
* reject job
* status update

### WMS

* stock movement
* adjustment
* picking
* packing
* inbound
* outbound

### Forwarding

* shipment creation
* container update
* document upload
* vessel update
* invoice creation

# 7. Scheduled Monitoring

# 7.1 Health Check

## Frequency

Every 10 minutes

---

## Checks

* API alive
* DB connection
* auth service
* cron execution
* Supabase latency

---

# 7.2 Operational Workflow Check

## Frequency

Every 30 minutes

---

## Trucking Checks

* JO stuck
* driver not accepted
* duplicate fleet assignment
* invalid WA token
* delivery overdue

---

## WMS Checks

* negative stock
* orphan inventory
* duplicate allocation
* picking not completed

---

## Forwarding Checks

* shipment status mismatch
* missing container
* missing documents
* overdue milestones

---

# 7.3 Deep Integrity Scan

## Frequency

Daily at 00:00

---

## Checks

* orphan records
* duplicate JO number
* invalid relationships
* inconsistent totals
* broken references

---

# 7.4 Cleanup Tasks

## Frequency

Daily at 02:00

---

## Tasks

* cleanup temp files
* retry failed queue
* archive logs
* remove stale sessions
