## 3. Forensic Audit Findings by Domain

### 3.1 ADR Integrity & Preservations (ADR-045..056)
- Verified: All 12 ADRs (`ADR-045` through `ADR-056`) are physically present in `docs/architecture/` with `Status: RATIFIED`.
- Numbering: Zero numbering collisions across all ADRs (`ADR-018` through `ADR-056`).

### 3.2 Generic Operational Handoff Contract (ADR-051)
- **Identity:** DB-generated UUID PK (`id`) + atomic sequence-backed `handoff_number` generated by PostgreSQL RPC `public.next_operational_handoff_number(p_tenant_id)` (`OH-YYYY-MM-NNNN`). Client generation is completely absent.
- **Polymorphic Reference:** Stored in `assigned_domain_reference JSONB` (`{ referenceType, referenceId, referenceNumber }`).
- **Scope & Lineage:** Each handoff is strictly scoped to `fulfillment_id` and `fulfillment_allocation_id` with foreign key integrity.

### 3.3 Tenant Security & Authorization Forensics
- **Tenant Derivation:** Exclusively derived from `IdentityContext.tenantId`. Zero references or trust in `x-tenant-id` header or client request body tenant overrides.
- **Row-Level Security:** Enforced at PostgreSQL layer via `operational_handoffs_isolation` policy (`tenant_id = public.get_my_tenant_id()`).
- **Authorization Gates:** Mutations invoke `assertPermission(context, 'commercial:manage')`; queries invoke `assertPermission(context, 'commercial:read')`.
- **Cross-Tenant Access:** Cross-tenant creation, lookup, and action execution are deterministically blocked with non-leaking errors (`HANDOFF_NOT_FOUND` / `FULFILLMENT_NOT_FOUND`).

### 3.4 Idempotency & Reliability Forensics (ADR-056)
- **Database Uniqueness:** Enforced via `CONSTRAINT uq_operational_handoff_idempotency UNIQUE (tenant_id, idempotency_key)`.
- **Handling:** Safe insert with PostgreSQL `23505` catch and re-select pattern. Duplicate submissions return the existing handoff record with `created: false`.

### 3.5 Lifecycle & State Machine Forensics
- **Enum `com_operational_handoff_status`**: Enforces 8 closed states: `ISSUED`, `ACKNOWLEDGED`, `ACCEPTED`, `EXECUTING`, `FULFILLED`, `FAILED`, `REJECTED`, `CANCELLED`.
- **Transitions Matrix:** Governed by `OPERATIONAL_HANDOFF_TRANSITIONS`. Illegal transitions (e.g. `ISSUED` $\to$ `EXECUTING`, `FULFILLED` $\to$ `EXECUTING`, `CANCELLED` $\to$ `ACCEPTED`) are blocked at runtime.

### 3.6 SBU Domain Sovereignty & Adapter Forensics
- **Forwarding Sovereignty (ADR-052):** `ForwardingHandoffAdapter` maps allocations to `shp_shipments` / `shp_execution_legs`. Forwarding domain owns POL, POD, MBL, HBL, carriers, vessels, and voyages. Operational Handoff contains 0 forwarding execution columns.
- **Customs Sovereignty (ADR-053):** `CustomsHandoffAdapter` coordinates declaration references and progressive attachment via `CustomsAttachmentService`. Customs domain owns CEISA 4.0, valuation, Permendag 36/2023 Lartas, and SHA-256 tamper-evident hash chain continuity.
- **Trucking Sovereignty & Lineage (ADR-054):** `TruckingHandoffAdapter` commands via `svc_service_requests(target_domain='TRUCKING')`. Lineage resolves via `trucking-lineage.ts` to `work_orders` $\to$ `wo_items` $\to$ `job_orders`. Direct writes to `job_orders` from handoff domain are strictly **0**.
- **Warehouse Sovereignty (ADR-055):** `WarehouseHandoffAdapter` commands via `svc_service_requests(target_domain='WAREHOUSE')` to WMS receipt orders and picking lists. Handoff contains 0 inventory, bin, or rack mechanics.

### 3.7 Cardinality & Guardrails
- Many SO $\to$ 1 WO: **STRICTLY FORBIDDEN** (ADR-037).
- Direct SO $\to$ JO, FL $\to$ JO, OH $\to$ JO: **STRICTLY FORBIDDEN**.
- Partial fulfillment and split shipment are supported through versioned revisions and multiple capability allocations per Sales Order.
