# ADR-001: Shared Kernel

## Context
SentraForge requires enterprise standardization. Uncontrolled dependencies create tight coupling.

## Decision
Centralize foundational DDD primitives.

## Evidence
`src/shared/kernel/`, `src/platform/logistics/`, and `src/infrastructure/` contain implementations.

## Consequences
Increased initial boilerplate (Generics, Interfaces) but massive long-term maintainability and loose coupling.

## Alternatives Considered
- Direct DB coupling (Rejected due to inability to swap Postgres for another DB).
- Exceptions for control flow (Rejected due to silent failures in TS).

## Future Review Trigger
Review when moving to Microservices.
