# Chapter 1

# Integration Philosophy

MySentra tidak boleh mengetahui struktur database.

Semua komunikasi dilakukan melalui API dan Business Services.

```text
MySentra

↓

Business API

↓

Sentralogis Core

↓

Database
```

Jika suatu hari database berubah, MySentra tidak perlu diubah.

---

# Chapter 2

# API Design Principles

## Principle 1

API First

Setiap fitur harus memiliki API terlebih dahulu.

Baru UI.

---

## Principle 2

Business Oriented

API tidak boleh bernama:

```
insert_job_order()
```

Tetapi:

```
generateJobOrders()
```

Karena API harus mewakili bisnis.

---

## Principle 3

Stateless

API tidak menyimpan session.

Context dikirim melalui JWT dan Request.

---

## Principle 4

Idempotent

Misalnya.

Generate JO.

Jika tombol diklik dua kali.

Tidak boleh menghasilkan dua JO.

# Chapter 22

# Business Capability Map

Daripada berpikir per modul, saya mengusulkan seluruh API dikelompokkan berdasarkan **Business Capability**:

| Capability          | Contoh API                     |
| ------------------- | ------------------------------ |
| Customer Management | Customer, Contact, Contract    |
| Order Management    | WO, WO Item, JO                |
| Resource Management | Driver, Fleet, Vendor          |
| Field Operations    | Timeline, Gate In, POD         |
| AI Operations       | Chat, OCR, Tool Calling        |
| Communication       | Notification, Chat, Attachment |
| Analytics           | KPI, Summary, Dashboard        |

Dengan cara ini, penambahan SBU Warehouse atau Depot cukup menambah capability baru, bukan membongkar API lama.

# 📌 Saya ingin mengusulkan perubahan besar yang menurut saya akan menjadi keunggulan Sentralogis

## Dari API menjadi Business Capabilities

Daripada mendokumentasikan sistem sebagai daftar endpoint, saya ingin seluruh blueprint menggunakan konsep **Business Capability Architecture**.

Contohnya:

* **Order Capability** → semua proses WO & JO.
* **Resource Capability** → Driver, Fleet, Vendor.
* **Execution Capability** → Gate In, Loading, Delivery.
* **Communication Capability** → Chat, Timeline, Notification.
* **AI Capability** → Conversation, OCR, Matching, Tool Calling.

Ini jauh lebih mudah dipahami oleh Product Owner, Business Analyst, dan Engineering. Endpoint API hanyalah implementasi teknis dari capability tersebut.
